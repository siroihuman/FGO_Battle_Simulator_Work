# 設計方針

仕様書バージョン: 1.0.0

## 技術構成

- React: 画面表示と操作状態
- TypeScript: 戦闘処理、型検査
- Vite: 開発と公開用ファイル生成
- Vitest: 計算・戦闘回帰テスト
- GitHub Pages: 公開

サーバー、外部API、ユーザーアカウントを必要としない静的Webアプリとします。

## 層の分離

| 層 | 責務 | 禁止事項 |
|---|---|---|
| `core` | 戦闘状態と進行 | UI要素の直接操作 |
| `formulas` | ダメージ、NP、スター等 | サーヴァント固有名の参照 |
| `effects` | 共通効果とトリガー | 固有効果の無制限な追加 |
| `ai` | 敵行動の選択 | 画面状態への依存 |
| `data` | 宣言的な対象データ | 任意コードの埋め込み |
| `mechanics` | 本当に固有な例外 | 共通効果の再実装 |
| `ui` | 入力と結果表示 | 独自の再計算 |
| `storage` | 保存、読込、リプレイ | 表示専用値の正本化 |

## 効果の3分類

### 通常処理

共通の効果データだけで再現できるものです。

例:

- 味方全体の攻撃力アップ
- 敵単体の防御力ダウン
- 自身のNP増加

### 限定的例外処理

効果自体は共通だが、付与タイミングや条件が特殊なものです。再利用可能な共通トリガーで扱います。

例:

- 攻撃時に自身の攻撃力アップ
- 被ダメージ時に攻撃者へ防御力ダウン
- ブレイク時に弱体付与

### 固有例外処理

他の対象へ再利用できない独自の状態変更や宝具換装等です。対象IDごとの個別ファイルへ分離します。

固有例外がない対象にはファイルを作りません。

## データ形式

- 基本データと共通効果は、検査可能な宣言的データで管理する。
- 固有ロジックだけTypeScriptの個別モジュールで管理する。
- すべてのデータに安定ID、名称、参照URL、仕様書バージョンを持たせる。
- 効果は説明文ではなく、実行順を持つ効果配列として保存する。
- 表示文は処理データと分離する。

## 乱数

単一のシードから用途別の独立乱数列を作ります。

- カード
- AI・対象
- 効果成功
- クリティカル
- ダメージ
- スター

効果を1つ追加しただけで無関係なダメージ乱数までずれないようにします。

## 保存互換

- 保存データへ仕様書バージョン、データ形式バージョン、乱数処理バージョンを記録する。
- ID変更時は移行処理を用意する。
- 当時のデータで再現する方法と、最新データで再計算する方法を分ける。

## 状態・効果基盤

- 戦闘中の各個体は、元データIDとは別の個体IDを持つ。
- 前衛は空き枠を保持し、控えは編成順を保持する。
- 対象解決は`src/effects/targeting.ts`だけで行い、個別データで配列を直接走査しない。
- 状態は`EffectTemplate`から`AppliedEffect`へ変換し、効果個体IDと登録順を採番する。
- 発動候補は、戦闘処理から渡された個体順、優先度、登録順で並べる。
- 発動条件の判定と子効果の付与成功判定は分離する。
- 控え中の個体は、明示的な例外フラグがない限り発動候補に含めず、残りターンも進めない。
- `src/effects/application.ts`は子効果ごとの成功率、耐性、回数制無効を1付与行動単位で解決する。
- `src/effects/modifiers.ts`は共通の成功率・耐性種別と分類限定照合を管理する。
- `src/effects/removal.ts`は解除候補の確定、解除成功率、解除耐性を管理する。
- `src/effects/actions.ts`はHP・NP・状態を変更する宣言的な共通アクションを記述順に実行する。
- `src/effects/actions.ts`の複数対象実行は編成順を維持し、HP吸収だけは全対象の減少後に吸収元へ1回回復する。
- `src/effects/maxHp.ts`は基礎最大HPと有効な最大HP変更状態から適用後最大HPを再計算し、付与・解除・期限切れ時の現在HPを調整する。
- `src/effects/hp.ts`は通常HP回復、HP1停止／HP0可能なHP減少、実減少量を使うHP吸収を管理する。
- `src/effects/hp.ts`は同一対象の通常毎ターン回復とスリップダメージを合算し、HP1～最大HPへ1回だけ丸める終了時精算も管理する。
- `src/effects/turnEnd.ts`は味方・敵別の終了時発動、対象解決、共通アクション実行、残りターン更新を統合する。
- ターン終了処理は開始時の発動候補と最終登録順を固定し、処理中に追加された状態を次回へ送る。
- 終了時効果の対象指定は状態所持者を基準とし、回復量等の付与者側補正には元の付与者を使用する。
- `turnEndSettlement`が指定された通常毎ターン回復・スリップは対象ごとに保留し、全候補の発動後、状態期限更新前に同時精算する。
- 同時精算指定のない遅延回復やその他の終了時効果は従来どおり発動順で即時実行する。
- `src/effects/defense.ts`は防御状態の優先順、貫通、攻撃／Hit単位の回数消費とダメージ式へ渡す防御値を管理する。
- `src/effects/survival.ts`は中間ブレイク、ガッツ、最終死亡、死亡時効果の可否を1か所で確定する。
- `src/effects/instantDeath.ts`は基礎即死率、成功率・耐性・無効を判定してから共通死亡処理を呼ぶ。
- 戦闘個体は`baseMaxHp`と`maxHp`を分けて保持し、一時的な最大HP状態を解除しても基礎値を失わない。
- 戦闘個体は敵・味方とも`deathRatePermille`を持ち、敵データ未設定時は0とする。
- 確率0%以下、100%以上、対象不在では乱数を消費しない。
