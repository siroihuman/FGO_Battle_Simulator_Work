# 設計方針

仕様書バージョン: 1.0.0

## 技術構成

- React: 画面表示と操作状態
- TypeScript: 戦闘処理、型検査
- Vite: 開発と公開用ファイル生成
- Vitest: 計算・戦闘回帰テスト
- GitHub Pages: 公開

サーバー、外部API、ユーザーアカウントを必要としない静的Webアプリとします。

## 層の分離

| 層 | 責務 | 禁止事項 |
|---|---|---|
| `core` | 戦闘状態と進行 | UI要素の直接操作 |
| `formulas` | ダメージ、NP、スター等 | サーヴァント固有名の参照 |
| `effects` | 共通効果とトリガー | 固有効果の無制限な追加 |
| `ai` | 敵行動の選択 | 画面状態への依存 |
| `data` | 宣言的な対象データ | 任意コードの埋め込み |
| `mechanics` | 本当に固有な例外 | 共通効果の再実装 |
| `ui` | 入力と結果表示 | 独自の再計算 |
| `storage` | 保存、読込、リプレイ | 表示専用値の正本化 |

## 効果の3分類

### 通常処理

共通の効果データだけで再現できるものです。

例:

- 味方全体の攻撃力アップ
- 敵単体の防御力ダウン
- 自身のNP増加

### 限定的例外処理

効果自体は共通だが、付与タイミングや条件が特殊なものです。再利用可能な共通トリガーで扱います。

例:

- 攻撃時に自身の攻撃力アップ
- 被ダメージ時に攻撃者へ防御力ダウン
- ブレイク時に弱体付与

### 固有例外処理

他の対象へ再利用できない独自の状態変更や宝具換装等です。対象IDごとの個別ファイルへ分離します。

固有例外がない対象にはファイルを作りません。

## データ形式

- 基本データと共通効果は、検査可能な宣言的データで管理する。
- 固有ロジックだけTypeScriptの個別モジュールで管理する。
- すべてのデータに安定ID、名称、参照URL、仕様書バージョンを持たせる。
- 効果は説明文ではなく、実行順を持つ効果配列として保存する。
- 表示文は処理データと分離する。

## 乱数

単一のシードから用途別の独立乱数列を作ります。

- カード
- AI・対象
- 効果成功
- クリティカル
- ダメージ
- スター

効果を1つ追加しただけで無関係なダメージ乱数までずれないようにします。

## 保存互換

- 保存データへ仕様書バージョン、データ形式バージョン、乱数処理バージョンを記録する。
- ID変更時は移行処理を用意する。
- 当時のデータで再現する方法と、最新データで再計算する方法を分ける。

## 戦闘進行基盤

- `src/core/battle/state.ts`は味方編成、現在の敵編成、残りWave、ターン数、進行フェーズ、現在使用分・次回味方コマンド用スター、全滅戦の結果を保持する。
- 戦闘開始時に味方前衛3騎、控え上限3騎、1～3Wave、敵同時出現3／6枠、敵参加数上限99体、個体ID重複を検査する。
- `WaveContinuationState`は前衛・控え以外のブレイク保留、復活保留、追加出現予定を保持し、いずれかが残る間はWave終了を防ぐ。
- `src/core/battle/progression.ts`は味方行動、味方ターン終了、敵行動、敵ターン終了の順序を検査し、終了処理完了後だけWave・勝敗を判定する。
- `src/core/battle/replacement.ts`は味方の自動交代と、敵の通常補充・即時補充を共通の編成更新として管理する。
- `src/core/battle/actionBoundary.ts`は1行動の全Hit・攻撃後効果が完了した境界だけで死亡者の退場、自動交代、敵補充を接続し、途中ではWave・勝敗・ブレイクを判定しない。
- 同モジュールは攻撃開始時の敵個体IDと元の前衛枠を対象アンカーとして保持し、対象消滅後は元の後方枠、前方への回り込み、元枠の順に次対象を決める。
- `src/core/battle/attack.ts`は固定された1体以上の対象へ、対象別総ダメージ、Hit分配、攻撃／Hit単位防御、HP・ブレイク・ガッツ・死亡、NP、スターを接続する。全体攻撃はHit番号、対象順で処理し、攻撃側状態を対象数だけ重複消費しない。
- 攻撃解決器は更新後の攻撃者・対象、対象別計算内訳、実行順のHit結果、NP・スター合計を返す。`src/core/battle/battleAttack.ts`は現在の戦闘個体を対象順へ正規化して攻撃を呼び、更新個体、ブレイク保留数、次回用スターを`BattleState`へ一括反映する。各Hit番号後のフックは同じ全体攻撃の全対象処理後に1回だけ呼び、そこで変わった戦闘状態を次Hitへ戻す。
- `src/core/battle/attackSequence.ts`は攻撃前、各Hit後、全Hit後の攻撃時、対象別被ダメージ時、攻撃後、連鎖する死亡時効果を1攻撃へ接続する。攻撃前効果後に計算入力を再構築し、トリガー結果と実攻撃結果を戦闘ログ向けに分けて返す。退場・自動交代・敵補充は引き続き外側の完了済み行動境界が担当する。
- `src/core/battle/actionData.ts`は戦闘個体IDごとのATK、クラス・属性、N/A・N/D、SR・SW・DTDR・DSR、カード別Hit、宝具・敵攻撃定義を戦闘開始前に検査して索引化する。同じデータIDの個体も別設定を保持できる。
- `src/core/battle/attackModifiers.ts`と`attackInput.ts`は攻撃前効果反映後の個体から通常補正を条件付きで合算し、相性、カード入力、ダメージ、攻撃時・被攻撃時NP、スター、防御文脈へ変換する。回数制防御の消費は従来どおり防御解決器だけが担当する。
- `src/core/battle/starState.ts`は現在使用分と次回味方コマンド用の2区分を各99個以内で管理する。現在分の加算・消費は味方行動中だけ許可し、次の味方行動へ入るターン終了境界では旧現在分を破棄して次回用だけを有効化する。
- 敵の戦闘不能者は1行動完了後の安全な境界で消滅させ、通常補充は敵ターン終了時、即時補充は次行動前にも、前方の空き枠から控え先頭の生存者を登場させる。
- 味方自動交代は移動記録とカードデッキ再構築要否を返し、カード基盤や戦闘ログが同じ判定を再実装しないようにする。
- 味方が全滅した場合も次回配布用カードデッキは空で保持でき、現在の行動終了後にターン終了コーディネーターが敗北を確定する。
- 敵補充は消滅・登場記録と通常補充の保留有無を返し、行動基盤と終了処理が安全な境界を明示して呼び分ける。
- 戦闘個体は現在HPゲージ番号、残りゲージ、ブレイク保留、最終ブレイクターンを保持し、`setBattleFormation`がWave継続用の保留数と同期する。
- `src/core/battle/break.ts`は味方ターン終了時の保留を前衛枠順、次に控え順で解決し、次ゲージの基礎最大HPと継続中の最大HP変更状態から全快値を再計算する。
- ブレイク基盤は後続コーディネーターが処理する`on_break`イベントを返し、固有効果や乱数処理をゲージ遷移へ埋め込まない。
- `src/effects/triggerExecution.ts`は`on_break`等の通常トリガーについて、親確率・回数、共通対象指定、子アクションを共通の順序で実行する。
- `src/effects/turnEnd.ts`は終了処理開始時の発動候補・登録順・前衛個体をスナップショットし、効果発動と期限更新をコーディネーターが分けて呼べる。
- `src/core/battle/cooldowns.ts`は生存前衛のスキルCTと魔術礼装3スキルのCTを0未満にせず更新する。
- `src/core/battle/turnEndCoordinator.ts`はブレイク、通常トリガー、毎ターン効果、死亡・交代、敵補充、期限、CT、Wave・勝敗判定を味方・敵別の確定順で接続する。
- `src/core/cards/deck.ts`は戦闘個体IDとカード番号で通常カードを識別し、15／10／5枚の未配布周期、5枚配布、周期枯渇・味方退場時の再構築を管理する。
- `src/core/cards/selection.ts`は現在手札と前衛宝具から重複なしの3枚選択を検査し、通常カード・宝具の実行直前判定と成立した宝具のNP消費を管理する。
- `src/core/cards/chain.ts`はカード確定時の位置・1stボーナス、同色／Mighty／Brave／宝具チェイン、Extra Attack、OC段階を乱数非消費の計算入力へ変換する。
- チェインエラーはカード確定時の行動不能状態から固定し、後続カードの実行直前判定とは分離する。これにより先行する補助宝具で行動不能を解除しても、後続カードだけを実行可能にし、失われたチェインは復元しない。
- `src/core/cards/critical.ts`は現在手札5枚について戦闘個体ごとのSWとカード限定スター集中度を集め、クリティカル用乱数列で最大50個を配分する。通常カード開始時には配分数と1stボーナスから0～100%のクリティカル率を作り、0%・100%を除いて同じ乱数列で判定する。
- `src/core/cards/turnCoordinator.ts`はArtsチェインNPを戦闘個体ごとに1回、最初のコマンドより前に加算した後、選択した3枚と成立済みExtra Attackを順番に進める。Quickチェインの次回用スター加算、実行直前判定、成立宝具のNP消費、実Hit解決器の呼び出し、共通行動境界、対象再選択を1行動ごとに接続する。
- `src/core/cards/commandAttack.ts`は通常カード番号、宝具安定ID、Extra Attackから個体別攻撃定義を選び、宝具Lv・OC、自動クリティカル結果、単体／全体対象を共通攻撃列へ渡す。攻撃数値未設定の通常カードではクリティカル抽選を開始しない。
- `src/core/battle/log.ts`は完了済み1行動から、表示用の個体参照、計算入力、対象別総ダメージ、Hit、防御・生存結果、NP・スター、トリガー、退場・登場、対象変更、乱数監査を状態本体と分離した形式バージョン付きJSONデータへ変換する。
- 味方・敵の具体的な攻撃実行器は、各実行器が所有する型付き不発理由と行動情報を共通ログ入力へ変換する。ログ層は攻撃・交代・対象選択を再計算せず、各解決器が返した確定結果だけを記録する。
- 実Hit解決器はダメージ・NP・スター・効果とそのログ詳細を返し、カードコーディネーターは計算式や個別データを複製しない。解決器が呼ばれない不発と、敵対象消滅による未開始の残りカードを区別する。
- 味方カード列が完了するか敵対象が尽きた後だけ味方ターン終了フェーズへ入り、Wave・勝敗判定は従来どおり終了処理の最後まで行わない。
- `src/ai/enemyTurn.ts`はクエスト固有AIの優先スキル要求と、現在の生存前衛・個別上限による通常3行動予定を分けて作る。優先処理後に通常予定を作ることで、死亡や即時補充を反映する。
- 敵AIが選んだ通常攻撃・スキル・宝具は実行直前に共通確認し、未設定や実行不能を通常結果として返す。宝具未設定時のチャージ0固定と、成立宝具のチャージ0化は戦闘状態側で保証する。
- `src/ai/enemyTurnCoordinator.ts`は優先スキルを設定順に完了し、その各行動境界まで反映した現在前衛から通常3枠を構築する。各通常枠では行動可能な場合だけ差し替え可能なAI選択器を呼び、実行直前確認、実効果解決器、共通行動境界を接続する。
- `src/ai/enemyAttack.ts`は敵通常攻撃・宝具の安定IDから攻撃定義を選び、既定の先頭単体対象または差し替え対象選択、全体対象、被攻撃時NPを共通攻撃列へ渡す。スキルと攻撃数値未設定は攻撃乱数非消費の記録可能な不発とする。
- 最小敵AIはフルチャージで設定済み宝具、それ以外は通常攻撃を要求する。スキルやクエスト固有選択は差し替えたAI選択器が担当し、行動不能・退場済み等の確定スキップではAI乱数を消費する選択器を呼ばない。
- 通常予定は優先処理後に1回固定し、通常行動中の退場者の残り予定を即時補充敵へ移さない。味方全滅時は残りの優先・通常行動を開始せず敵ターン終了へ進む。
- 味方カード列、味方ターン終了、敵行動列、敵ターン終了は同じ`BattleState`を順に受け渡し、1戦闘ターン後の味方行動フェーズまで接続できる。勝利・敗北は従来どおり対応するターン終了の最終地点だけで確定する。
- 戦闘状態は現在の5枚、未配布カード、配布周期、再構築理由を保持し、Wave移行と前衛順変更では同じデッキ状態を引き継ぐ。
- 宝具カードは戦闘個体IDで識別し、戦闘個体の上位宝具定義、宝具Lv、カード色を参照する。行動不能は共通分類・フラグ、宝具封印は共通効果種別・フラグから判定する。
- `src/effects/classification.ts`の共通行動不能判定を、味方カードと敵行動の両方から使用する。
- 味方ターン終了コーディネーターと敵ターン終了コーディネーターは、味方退場信号がある場合だけ自動交代後の前衛から次回配布用デッキを再構築する。
- ターン数は開始済みの味方行動フェーズ数とし、次Waveへ進む時も戦闘通算ターンを増やしてWaveターンだけ1へ戻す。
- 同時全滅は味方全滅を先に判定して敗北とし、特殊勝敗条件を進行基盤へ持ち込まない。

## 戦闘ログと乱数監査

- 戦闘ログは完了済み1行動を最小単位とし、Wave番号、戦闘ターン、Waveターン、行動側、行動番号から決定的なIDを作る。
- `BattleState`、関数、`Map`等はログへ保存せず、個体ID・データID・名称と計算・結果のプリミティブだけをJSONへ保存する。
- 味方コマンド開始前のスター配分乱数は行動ログと分けた設定時乱数として記録し、カードごとのクリティカル、効果、ダメージ、スター抽選は所属する行動へ記録する。
- `DeterministicRng`の監査リスナーは乱数列を進めず、整数抽選の範囲・値、確率判定の率・抽選値・成否、内部抽選番号を観測する。0%・100%の確定判定も抽選値なし・消費0回として記録する。
- 現段階のログ対象は味方コマンド列と敵行動列である。ターン終了、Wave移行、最終勝敗のログは完全戦闘エンジン接続時に同じ形式へ追加する。

## 状態・効果基盤

- 戦闘中の各個体は、元データIDとは別の個体IDを持つ。
- 前衛は空き枠を保持し、控えは編成順を保持する。
- 対象解決は`src/effects/targeting.ts`だけで行い、個別データで配列を直接走査しない。
- 状態は`EffectTemplate`から`AppliedEffect`へ変換し、効果個体IDと登録順を採番する。
- 発動候補は、戦闘処理から渡された個体順、優先度、登録順で並べる。
- 発動条件の判定と子効果の付与成功判定は分離する。
- 控え中の個体は、明示的な例外フラグがない限り発動候補に含めず、残りターンも進めない。
- `src/effects/application.ts`は子効果ごとの成功率、耐性、回数制無効を1付与行動単位で解決する。
- `src/effects/modifiers.ts`は共通の成功率・耐性種別と分類限定照合を管理する。
- `src/effects/removal.ts`は解除候補の確定、解除成功率、解除耐性を管理する。
- `src/effects/actions.ts`はHP・NP・状態を変更する宣言的な共通アクションを記述順に実行する。
- `src/effects/actions.ts`の複数対象実行は編成順を維持し、HP吸収だけは全対象の減少後に吸収元へ1回回復する。
- `src/effects/maxHp.ts`は基礎最大HPと有効な最大HP変更状態から適用後最大HPを再計算し、付与・解除・期限切れ時の現在HPを調整する。
- `src/effects/hp.ts`は通常HP回復、HP1停止／HP0可能なHP減少、実減少量を使うHP吸収を管理する。
- `src/effects/hp.ts`は同一対象の通常毎ターン回復とスリップダメージを合算し、HP1～最大HPへ1回だけ丸める終了時精算も管理する。
- `src/effects/turnEnd.ts`は味方・敵別の終了時発動、対象解決、共通アクション実行、残りターン更新を統合する。
- ターン終了処理は開始時の発動候補と最終登録順を固定し、処理中に追加された状態を次回へ送る。
- 終了時効果の対象指定は状態所持者を基準とし、回復量等の付与者側補正には元の付与者を使用する。
- `turnEndSettlement`が指定された通常毎ターン回復・スリップは対象ごとに保留し、全候補の発動後、状態期限更新前に同時精算する。
- 同時精算指定のない遅延回復やその他の終了時効果は従来どおり発動順で即時実行する。
- `src/effects/defense.ts`は防御状態の優先順、貫通、攻撃／Hit単位の回数消費とダメージ式へ渡す防御値を管理する。攻撃側状態と対象側状態を分けて解決でき、全体攻撃で攻撃側状態を対象ごとに重複消費しない。
- `src/effects/survival.ts`は中間ブレイク、ガッツ、最終死亡、死亡時効果の可否を1か所で確定する。
- `src/effects/instantDeath.ts`は基礎即死率、成功率・耐性・無効を判定してから共通死亡処理を呼ぶ。
- 戦闘個体は`baseMaxHp`と`maxHp`を分けて保持し、一時的な最大HP状態を解除しても基礎値を失わない。
- 戦闘個体は敵・味方とも`deathRatePermille`を持ち、敵データ未設定時は0とする。
- 確率0%以下、100%以上、対象不在では乱数を消費しない。
