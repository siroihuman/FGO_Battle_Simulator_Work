# 設計方針

仕様書バージョン: 1.0.0

## 技術構成

- React: 画面表示と操作状態
- TypeScript: 戦闘処理、型検査
- Vite: 開発と公開用ファイル生成
- Vitest: 計算・戦闘回帰テスト
- GitHub Pages: 公開

サーバー、外部API、ユーザーアカウントを必要としない静的Webアプリとします。

## 層の分離

| 層 | 責務 | 禁止事項 |
|---|---|---|
| `core` | 戦闘状態と進行 | UI要素の直接操作 |
| `formulas` | ダメージ、NP、スター等 | サーヴァント固有名の参照 |
| `effects` | 共通効果とトリガー | 固有効果の無制限な追加 |
| `ai` | 敵行動の選択 | 画面状態への依存 |
| `data` | 宣言的な対象データ | 任意コードの埋め込み |
| `mechanics` | 本当に固有な例外 | 共通効果の再実装 |
| `ui` | 入力と結果表示 | 独自の再計算 |
| `core/battle/session` | 保存用セッション、読込、リプレイ照合 | 表示専用値の正本化・関数型AIの保存 |
| `core/battle/loadout` | 魔術礼装・概念礼装選択と開始時適用 | 初回配布後の再適用・未対応効果の近似 |
| `ui/initialBattle` | 登録済み初期データから戦闘開始入力と`BattleSession`を構築 | 能力値・効果・対象・乱数の独自計算 |
| `ui/battlePresentation` | 保存済み状態・行動ログ・ターンログの表示用整形 | 戦闘結果・退場・チャージ進行の再実行 |

## 効果の3分類

### 通常処理

共通の効果データだけで再現できるものです。

例:

- 味方全体の攻撃力アップ
- 敵単体の防御力ダウン
- 自身のNP増加

### 限定的例外処理

効果自体は共通だが、付与タイミングや条件が特殊なものです。再利用可能な共通トリガーで扱います。

例:

- 攻撃時に自身の攻撃力アップ
- 被ダメージ時に攻撃者へ防御力ダウン
- ブレイク時に弱体付与

### 固有例外処理

他の対象へ再利用できない独自の状態変更や宝具換装等です。対象IDごとの個別ファイルへ分離します。

固有例外がない対象にはファイルを作りません。

## データ形式

- 基本データと共通効果は、検査可能な宣言的データで管理する。
- 固有ロジックだけTypeScriptの個別モジュールで管理する。
- すべてのデータに安定ID、名称、参照URL、仕様書バージョンを持たせる。
- 効果は説明文ではなく、実行順を持つ効果配列として保存する。
- 表示文は処理データと分離する。

### サーヴァントデータ

- `src/data/servants/schema.ts`は形式バージョン1、レアリティ別8段階Lv、カードとHit、戦闘用基礎率、特性、上位スキル3つ、全クラススキル、上位宝具1つ、出典を型として固定する。
- サーヴァントの`dataId`は英小文字の安定したプロジェクトIDとし、Wikiのページ番号やゲーム内通し番号は使わない。通し番号は外部メタデータ、Wiki URLは出典として別に保存する。
- スキル・クラススキル・宝具の効果は資料の記述順に1から連続する`order`を持ち、説明文だけで実行処理を表さない。
- 対象は自身、味方、敵、単体、全体、先頭、最後尾、控えを含む、自身を除く、必要特性を組み合わせる。再利用データへ戦闘個体IDは保存しない。
- `src/data/servants/validation.ts`は強化後のみ、スキルLv最大、レアリティ別Lv、5枚カード、Hit、倍率、3スキル、効果順、全データ内の安定ID重複、出典URL・確認日を登録前に検査する。
- `src/data/servants/registry.ts`は`dataId`で定義を索引化し、選択Lv・宝具Lv・装備加算値と戦闘個体IDから`BattleUnitState`と`CombatantAttackData`を作る。同じ`dataId`から複数個体を作っても選択値を共有しない。
- 同アダプターはクラススキル、保有スキル、宝具の非攻撃効果を戦闘個体別の`CombatantActionEffectData`へ変換する。宝具は資料順の攻撃位置と非攻撃効果を分離して保持する。
- 共通効果実行層へ未接続の効果と条件付き特攻は`unresolvedEffectStableIds`へ明示する。未接続効果を無条件効果へ置き換えたり、実装済みとして表示したりしない。

### 宣言的行動効果

- `src/effects/declarations.ts`は実行する効果、対象、固定値・宝具Lv.1～5別値・OC1～5別値を型付きデータとして定義する。未対応効果は`unsupported`と安定した機構IDで明示する。
- `src/effects/actionData.ts`は戦闘個体ごとのクラススキル群、保有スキル、宝具効果列を登録前に検査する。保有スキルはスロットと最大Lv時CT、宝具は攻撃位置を持ち、効果と攻撃の資料順が1から連続していることを保証する。
- `src/effects/actionExecution.ts`は単体対象を実行時の個体IDで補い、現在編成から対象を毎効果解決し、既存の共通HP・NP・状態付与・解除・即死・CT短縮・現在NP倍率・敵チャージ増減処理へ渡す。直接NP増減と現在NP倍率の上限は各対象の宝具Lvを使用する。スター獲得は戦場状態操作として現在使用分／次回用の行先を宣言する。
- カード再配布は`redistribute_command_cards`を再利用可能な宣言的戦場操作として実装する。個体対象の共通HP・NP処理や個別`mechanics`へ近似せず、現在前衛からのデッキ再構築、カード用乱数による5枚配布、入力境界のスター配分確定を共通コーディネーターへ委ねる。
- `src/effects/noblePhantasmCardType.ts`は固有の宝具カード種別を書き換えず、付与中の宝具カード種別変更を登録順で解決する。複数ある場合は最新を優先し、解除・期限切れで直前の変更または固有種別へ戻す。変更状態は強化として登録し、不正な種別・分類を効果適用前に拒否する。
- クラススキル初期化は味方前衛、味方控え、敵前衛、敵控えの編成順で共通効果を1回適用し、効果個体IDと登録順を戦闘全体で採番する。
- `src/effects/skillExecution.ts`は味方行動中の生存前衛、スキルCT、単体対象、未対応効果を乱数使用前に検査する。成立時は使用スキルのCTを先に設定してから資料順に効果を実行し、最後に死亡・自動交代の完了済み行動境界を通す。コマンドカード行動数は消費しない。
- 未対応効果を含む保有スキル・宝具・敵スキルは近似実行せず、状態、CT、NP、敵チャージ、乱数を変更しない。
- 宝具効果列は`attackOrder`で攻撃前後へ分け、共通`before_attack`後と共通`after_attack`後のフックから同じ効果採番・効果乱数列へ渡す。攻撃前効果完了後の生存対象だけでHit入力を再構築し、攻撃後効果の後に死亡時列と行動境界を処理する。
- 敵スキルの指定単体対象はAI要求にだけ保持し、再利用データへ戦闘個体IDを保存しない。宣言効果未登録の敵スキルは安全な不発を維持する。

### 魔術礼装・概念礼装データ

- `src/data/mysticCodes`は形式バージョン2として、安定ID、Lv最大方針、資料順の3スキル、最大Lv時CT、宣言効果または直接オーダーチェンジ、出典を検査する。アトラス院制服、ノーマルカルデア制服、魔術協会制服を別の安定IDで登録する。`mage-association-uniform`は共通`heal_hp`、`change_np`、`redistribute_command_cards`だけへ接続する。
- `src/effects/mysticCodeExecution.ts`は選択データ、使用フェーズ、対象、CT、未対応効果を変更前に検査し、通常効果を戦闘個体を持たない味方側発生源として共通効果へ渡す。オーダーチェンジは`src/core/battle/replacement.ts`の直接交換を使い、カードデッキを再構築しない。
- `src/data/craftEssences`は形式バージョン1として、安定ID、レアリティ、最大解放／未解放、選択Lv、最終ATK・HP、開始時宣言効果、出典を検査する。状態として付与する概念礼装効果は解除不能だけを受理する。
- `src/data/craftEssences/initialCraftEssences.ts`はカレイドスコープと黒の聖杯の最大解放・星5Lv100定義を登録する。開始NP、宝具威力、毎ターンHP減少は既存の共通アクション・共通状態・ターン終了トリガーだけを使用する。
- `src/core/battle/loadout.ts`は初回カード配布前に選択IDを登録済みデータへ解決し、概念礼装ATK・HPを戦闘個体別データへ加え、開始時効果をクラススキルと同じ共通受動効果初期化へ渡す。
- 登録漏れ、味方以外への装備、個体別攻撃データ不足、未対応開始時効果は状態・効果採番・乱数を変更する前に拒否する。礼装なしは空選択として正常に初期化する。
- 初期概念礼装は定義側で最大解放・レアリティ別最大Lvを固定し、選択側は戦闘個体IDから`dataId`への0～1件の対応だけを持つ。所持枚数を管理せず、同じ`dataId`の複数個体選択を許可する。
- 形式1定義、既存の戦闘個体別選択、`SelectedCraftEssenceState`が解放状態・Lv・最終ATK・HPを保持できるため、初期2枚の仕様確定では概念礼装データ形式を拡張しない。これらの値は現在の中断保存形式4にもそのまま保持する。

### 初期戦闘UI接続

- `src/ui/initialBattle.ts`は画面入力を保持するUI状態と戦闘エンジン状態の境界とする。前衛3騎、控え0～3騎、個体別Lv・宝具Lv・概念礼装、魔術礼装、固定極級敵設定、固定シードの登録有無だけを検査する。
- 成立設定は、サーヴァントと敵の既存アダプターで個体別状態・攻撃・行動効果データへ変換し、`createBattleState`、`initializeBattleLoadout`、`createBattleSession`の順に渡す。ロードアウト初期化後・初回配布前の状態をセッション初期スナップショットとする。
- `src/ui/battlePresentation.ts`は`BattleState`、`BattleTurnLog`、内包する`BattleLogBatch`の保存済み確定値を簡潔表示へ整形する。ダメージ、対象、クリティカル、退場・登場、敵チャージ、Wave・勝敗を再解決しない。
- React画面はカードIDとユーザー選択対象IDを`resolveBattleSessionTurn`へ渡し、不成立理由も同結果から表示する。中断保存は`serializeBattleSuspendSave`、読込は`parseBattleSuspendSave`と`restoreBattleSession`を使用し、ロードアウト・開始時効果・敵チャージを再適用しない。
- 入力中の初期設定だけをブラウザーのローカル保存へJSON保存する。戦闘の正本は常に`BattleSession`であり、React stateやローカル保存へ計算済み戦闘値を別管理しない。

### 敵データ

- `src/data/enemies`は形式1の敵定義、登録時検査、レジストリを持つ。再利用定義は安定`dataId`、正式名称、通常敵／サーヴァント等の区分、クラス、属性、特性、基礎率、通常攻撃、スキル、チャージ攻撃、個体別行動上限、出典を持つ。
- 段階別敵宝具は、再利用定義の固定値／宝具Lv別5値／OC別5値と、戦闘設定が戦闘個体・宝具行動ごとに明示する宝具Lv／最終OCを分離する。変換時に必要な軸だけを照合し、JSON安全な文脈と宣言値を既存の個体別攻撃・行動効果データへ保持する。敵Lv、現在／最大チャージ、ターン、Waveから段階を推定しない。
- Wave、配置、戦闘個体ID、Lv、HP、ATK、開始チャージ、ブレイク、控え、補充方式は初期戦闘設定へ分離し、敵定義へ埋め込まない。同じ敵`dataId`から複数個体を作っても現在状態と個体別数値を共有しない。
- 初期対象は`radiant-arm-of-dawn-saber`（黎明の炎腕・剣）1種と、`ember-gathering-saber-extreme`（種火集め・剣基準・極級）の3 Wave・7個体であり、形式1データから個体別状態・攻撃・行動効果データへ戦闘開始前に変換する。
- レジストリは戦闘開始前に敵定義と初期戦闘設定を一括検査し、戦闘個体ID別の`BattleUnitState`、`CombatantAttackData`、必要な`CombatantActionEffectData`へ変換する。不正・未対応値は状態・チャージ・乱数変更前に拒否する。
- ランダム単体対象はJSON化できる安定方針IDからAI・対象用乱数列を使用し、敵通常攻撃のクリティカルは共通クリティカル用乱数列を使用する。保存不能な関数型AIを初期敵の通常方針にしない。
- 敵ターン終了時の通常チャージ増加は共通終了時処理とし、チャージ攻撃を持つ生存前衛だけを1増加して最大値で制限する。控えとチャージ攻撃未設定敵は進行させない。

## 乱数

単一のシードから用途別の独立乱数列を作ります。

- カード
- AI・対象
- 効果成功
- クリティカル
- ダメージ
- スター

効果を1つ追加しただけで無関係なダメージ乱数までずれないようにします。

## 保存互換

- 保存データへ仕様書バージョン、データ形式バージョン、乱数処理バージョンを記録する。
- ID変更時は移行処理を用意する。
- 当時のデータで再現する方法と、最新データで再計算する方法を分ける。
- `src/core/battle/session.ts`は開始時・現在の入力境界スナップショット、戦闘個体別攻撃／行動効果データ、装備選択、選択に使用した魔術礼装データ、カード／サーヴァントスキル／魔術礼装スキル操作履歴、入力境界ログ、蓄積ターンログを形式4としてJSON保存する。再開は現在値を直接復元し、リプレイは開始値と履歴から再実行して保存済みの状態・乱数・ログと照合する。形式3は効果を再実行せず直接移行し、当時存在しなかった入力境界ログだけを不完全と明記する。

## 戦闘進行基盤

- `src/core/battle/state.ts`は味方編成、現在の敵編成、残りWave、ターン数、進行フェーズ、現在使用分・次回味方コマンド用スター、全滅戦の結果を保持する。
- 戦闘開始時に味方前衛3騎、控え上限3騎、1～3Wave、敵同時出現3／6枠、敵参加数上限99体、個体ID重複を検査する。
- `WaveContinuationState`は前衛・控え以外のブレイク保留、復活保留、追加出現予定を保持し、いずれかが残る間はWave終了を防ぐ。
- `src/core/battle/progression.ts`は味方行動、味方ターン終了、敵行動、敵ターン終了の順序を検査し、終了処理完了後だけWave・勝敗を判定する。
- `src/core/battle/replacement.ts`は味方の自動交代と、敵の通常補充・即時補充を共通の編成更新として管理する。
- `src/core/battle/actionBoundary.ts`は1行動の全Hit・攻撃後効果が完了した境界だけで死亡者の退場、自動交代、敵補充を接続し、途中ではWave・勝敗・ブレイクを判定しない。同じ味方戦闘個体の単体通常カード連続では、選択対象の敵退場だけを明示的に次の連続区間境界へ送り、他の退場と味方交代は通常どおり処理する。
- 同モジュールは攻撃開始時の敵個体IDと元の前衛枠を対象アンカーとして保持し、対象消滅後は元の後方枠、前方への回り込み、元枠の順に次対象を決める。
- `src/core/battle/attack.ts`は固定された1体以上の対象へ、対象別総ダメージ、Hit分配、攻撃／Hit単位防御、HP・ブレイク・ガッツ・死亡、NP、スターを接続する。全体攻撃はHit番号、対象順で処理し、攻撃側状態を対象数だけ重複消費しない。
- 攻撃解決器は更新後の攻撃者・対象、対象別計算内訳、実行順のHit結果、NP・スター合計を返す。`src/core/battle/battleAttack.ts`は現在の戦闘個体を対象順へ正規化して攻撃を呼び、更新個体、ブレイク保留数、次回用スターを`BattleState`へ一括反映する。各Hit番号後のフックは同じ全体攻撃の全対象処理後に1回だけ呼び、そこで変わった戦闘状態を次Hitへ戻す。
- `src/core/battle/attackSequence.ts`は攻撃前、各Hit後、全Hit後の攻撃時、対象別被ダメージ時、攻撃後、連鎖する死亡時効果を1攻撃へ接続する。各イベントは通常コマンド／宝具／Extra／敵通常攻撃の種別とQuick／Arts／Buster／Extraのカード種別を保持する。宝具固有の攻撃前／後宣言効果用フックを共通トリガー列の決められた位置へ挿入し、攻撃前効果後に生存対象と計算入力を再構築する。退場・自動交代・敵補充は引き続き外側の完了済み行動境界が担当する。
- `src/core/battle/actionData.ts`は戦闘個体IDごとのATK、クラス・属性、N/A・N/D、SR・SW・DTDR・DSR、カード別Hit、宝具・敵攻撃定義、敵宝具の任意段階文脈、宝具特殊威力の必須対象特性を戦闘開始前に検査して索引化する。同じデータIDの個体も別設定を保持できる。
- `src/core/battle/attackModifiers.ts`と`attackInput.ts`は攻撃前効果反映後の個体から通常補正を条件付きで合算し、相性、カード入力、ダメージ、攻撃時・被攻撃時NP、スター、防御文脈へ変換する。条件付き宝具特殊威力は対象ごとの有効特性をすべて満たす場合だけ入力し、回数制防御の消費は従来どおり防御解決器だけが担当する。
- `src/core/battle/starState.ts`は現在使用分と次回味方コマンド用の2区分を各99個以内で管理する。現在分の加算・消費は味方行動中だけ許可し、宣言効果と攻撃トリガーからの獲得も行先を明示して同じ上限処理を使う。攻撃時発動とターン終了時発動からのスター獲得は次回用へ加算する。次の味方行動へ入るターン終了境界では旧現在分を破棄して次回用だけを有効化する。
- ターン終了トリガーのスター獲得は、編成だけを扱う`src/effects/turnEnd.ts`が各子アクション位置で確定済み加算要求を戦闘状態所有者へ渡し、`src/core/battle/turnEndCoordinator.ts`が`addNextCommandStars`を即時適用する。`command`指定と不正宣言は`src/effects/runtime.ts`で登録前に拒否し、`turnLog.ts`へ要求量・加算前・実加算量・加算後・上限超過量を任意項目として保存する。`battlePresentation.ts`は保存値だけを整形し、終了時効果解決器、ログ、UIのいずれもスター寿命や上限を重複実装しない。
- 敵の戦闘不能者は1行動完了後の安全な境界で消滅させ、通常補充は敵ターン終了時、即時補充は次行動前にも、前方の空き枠から控え先頭の生存者を登場させる。
- 味方自動交代は移動記録とカードデッキ再構築要否を返し、カード基盤や戦闘ログが同じ判定を再実装しないようにする。
- 味方が全滅した場合も次回配布用カードデッキは空で保持でき、現在の行動終了後にターン終了コーディネーターが敗北を確定する。
- 敵補充は消滅・登場記録と通常補充の保留有無を返し、行動基盤と終了処理が安全な境界を明示して呼び分ける。
- 戦闘個体は現在HPゲージ番号、残りゲージ、ブレイク保留、最終ブレイクターンを保持し、`setBattleFormation`がWave継続用の保留数と同期する。
- `src/core/battle/break.ts`は味方ターン終了時の保留を前衛枠順、次に控え順で解決し、次ゲージの基礎最大HPと継続中の最大HP変更状態から全快値を再計算する。
- ブレイク基盤は後続コーディネーターが処理する`on_break`イベントを返し、固有効果や乱数処理をゲージ遷移へ埋め込まない。
- `src/effects/triggerExecution.ts`は`on_break`等の通常トリガーについて、親確率・回数、共通対象指定、子アクションを共通の順序で実行する。攻撃種別・カード種別の条件は候補収集時に照合し、不一致なら親確率判定より前に除外して回数も効果乱数も消費しない。攻撃イベントでは個体更新に加え、戦場スター獲得を明示された区分へ適用する。
- `src/effects/turnEnd.ts`は終了処理開始時に終了側の発動候補・登録順と双方の前衛個体をスナップショットし、効果発動と`owner_turn_end`／`opponent_turn_end`期限更新をコーディネーターが分けて呼べる。終了時トリガーは終了側だけ、期限更新は明示境界が一致する双方の前衛だけを対象とする。
- `src/core/battle/cooldowns.ts`は生存前衛のスキルCTと魔術礼装3スキルのCTを0未満にせず更新する。
- `src/core/battle/turnEndCoordinator.ts`はブレイク、通常トリガー、毎ターン効果、死亡・交代、敵補充、期限、CT、Wave・勝敗判定を味方・敵別の確定順で接続する。
- `src/core/cards/deck.ts`は戦闘個体IDとカード番号で通常カードを識別し、15／10／5枚の未配布周期、5枚配布、周期枯渇・味方退場時の再構築を管理する。カード再配布は旧手札・残り・配布済みを破棄し、現在前衛の全カードから新周期の5枚を原子的に確定する共通入口を使用する。
- `src/core/cards/selection.ts`は現在手札と前衛宝具から重複なしの3枚選択を検査し、通常カード・宝具の実行直前判定と成立した宝具のNP消費を管理する。
- `src/core/cards/chain.ts`はカード確定時の位置・1stボーナス、同色／Mighty／Brave／宝具チェイン、Extra Attack、OC段階を乱数非消費の計算入力へ変換する。
- チェインエラーはカード確定時の行動不能状態から固定し、後続カードの実行直前判定とは分離する。これにより先行する補助宝具で行動不能を解除しても、後続カードだけを実行可能にし、失われたチェインは復元しない。
- `src/core/cards/critical.ts`は現在手札5枚について戦闘個体ごとのSWとカード限定スター集中度を集め、クリティカル用乱数列で最大50個を配分する。新規セッションの配分結果は入力境界状態へ保存し、通常カード開始時には保存済み配分数と1stボーナスから0～100%のクリティカル率を作る。0%・100%を除く判定だけを同じ乱数列の続きで行う。
- `src/core/cards/turnCoordinator.ts`はArtsチェインNPを戦闘個体ごとに1回、最初のコマンドより前に加算した後、選択した3枚と成立済みExtra Attackを順番に進める。Quickチェインの次回用スター加算、実行直前判定、成立宝具のNP消費、実Hit解決器の呼び出し、共通行動境界、対象再選択を1行動ごとに接続する。同一戦闘個体・単体・通常カードの連続を先読みし、倒した対象を次の通常カードまたはExtra Attackまで保持するが、宝具・全体攻撃・別個体への切替では従来の境界を使う。各行動結果は戦闘不能対象への連続かを確定フラグで返し、`src/ui/battleUi.ts`はそのフラグが立った成立攻撃だけ攻撃完了直前の確定状態を選ぶ。`src/App.tsx`は資源増減0でも連続フレームを作り、撃破対象のHP0表示後に確定行動境界の退場を表示する。
- `src/core/cards/commandAttack.ts`は通常カード番号、宝具安定ID、Extra Attackから個体別攻撃定義を選び、宝具Lv・OC、自動クリティカル結果、単体／全体対象と攻撃種別・カード種別を共通攻撃列へ渡す。任意の行動効果レジストリがある宝具は、同じ宝具Lv・OC文脈で攻撃前後効果を実行する。攻撃数値未設定の通常カードではクリティカル抽選を開始しない。
- `src/core/battle/battleTurn.ts`は単一の`BattleRng`と効果採番を味方カード列、味方ターン終了、敵行動列、敵ターン終了へ順に受け渡す。成立したコマンド列の後は終了処理を必ず実行し、勝敗確定または次Wave開始なら敵行動を開始せず、通常時は次の味方入力地点まで進める。
- `src/core/battle/log.ts`は完了済み1行動または味方入力境界の能動スキルから、表示用の個体参照、計算入力、宣言効果の段階・対象・実行結果、CT前後、敵チャージ差分、宣言スター獲得、対象別総ダメージ、Hit、防御・生存結果、NP・スター、トリガー、退場・登場、対象変更、直接オーダーチェンジ、乱数監査を状態本体と分離した形式バージョン5のJSONデータへ変換する。
- `src/core/battle/turnLog.ts`は行動ログを再計算せず時系列レコードへ包み、双方の終了時発動・合算HP精算・ブレイク・敵通常チャージ増加前後・期限・CT・交代、Wave移行・勝敗の確定結果を形式バージョン2の同じ1戦闘ターンログへ追加する。親シード、乱数処理バージョン、開始前後の全乱数列位置も保存する。
- `src/core/battle/session.ts`は入力境界の`BattleLoop`、能動スキル入力ログ、蓄積ターンログをまとめ、JSON化できるカード・対象・サーヴァントスキル・魔術礼装スキル・オーダーチェンジ・優先スキル入力だけを履歴化する。カード再配布の成立結果は既存スキル操作に所属させ、抽選カードIDを操作入力へ保存しない。事前拒否は履歴・ログも変更せず、関数型AI選択器と同様に未表現の選択を補完しない。
- 新規セッションは入力境界確定済みのカード別スター配分を状態に保持する。中断保存は形式4・データ1.38.0とし、形式4・データ1.37.0以前の保存は旧来のカード確定時配分方式を明示する互換モードで直接復元し、再配布が初めて成立した境界から新方式へ移す。移行時に手札・スター・乱数を再実行しない。
- 敵宝具段階文脈は旧固定値データを壊さない任意のJSONデータとして戦闘個体別`attackData`／`actionEffectData`へ含めるため、中断保存形式4・データ1.38.0を維持する。直接再開は保存済み文脈・宣言・ログを直接復元し、現在の敵レジストリから段階を再選択しない。
- この敵宝具段階文脈経路は統合受入済みであり、形式1登録、原子的事前不発、同一スナップショット、固定値業火互換、型付きログ、形式4・データ1.38.0の直接復元、固定シードリプレイ、UI非再計算を回帰検査で固定する。
- 味方・敵の具体的な攻撃実行器は、各実行器が所有する型付き不発理由と行動情報を共通ログ入力へ変換する。ログ層は攻撃・交代・対象選択を再計算せず、各解決器が返した確定結果だけを記録する。
- 実Hit解決器はダメージ・NP・スター・効果とそのログ詳細を返し、カードコーディネーターは計算式や個別データを複製しない。解決器が呼ばれない不発と、敵対象消滅による未開始の残りカードを区別する。
- 味方カード列が完了するか敵対象が尽きた後だけ味方ターン終了フェーズへ入り、Wave・勝敗判定は従来どおり終了処理の最後まで行わない。
- `src/ai/enemyTurn.ts`はクエスト固有AIの優先スキル要求と、現在の生存前衛・個別上限による通常3行動予定を分けて作る。優先処理後に通常予定を作ることで、死亡や即時補充を反映する。
- 敵AIが選んだ通常攻撃・スキル・宝具は実行直前に共通確認し、未設定や実行不能を通常結果として返す。宝具未設定時のチャージ0固定と、成立宝具のチャージ0化は戦闘状態側で保証する。
- `src/ai/enemyTurnCoordinator.ts`は優先スキルを設定順に完了し、その各行動境界まで反映した現在前衛から通常3枠を構築する。各通常枠では行動可能な場合だけ差し替え可能なAI選択器を呼び、NP・チャージ消費前の宣言効果ガード、実行直前確認、実効果解決器、共通行動境界を接続する。
- `src/ai/enemyAttack.ts`は敵通常攻撃・宝具の安定IDから攻撃定義を選び、既定の先頭単体対象または差し替え対象選択、全体対象、被攻撃時NP、敵通常攻撃／宝具の攻撃種別とカード種別を共通攻撃列へ渡す。行動効果レジストリがある敵スキルと敵宝具前後効果を同じ共通効果実行器へ渡し、宣言効果未登録のスキルと攻撃数値未設定は乱数非消費の記録可能な不発とする。段階別敵宝具は`enemyNoblePhantasmContext.ts`で対象抽選・チャージ0化より前に攻撃倍率と全宣言効果に必要な宝具Lv・OCを一括検査し、事前確認結果に保持した同じ不変スナップショットを攻撃前後とログへ渡す。
- 最小敵AIはフルチャージで設定済み宝具、それ以外は通常攻撃を要求する。スキルやクエスト固有選択は差し替えたAI選択器が担当し、行動不能・退場済み等の確定スキップではAI乱数を消費する選択器を呼ばない。
- 通常予定は優先処理後に1回固定し、通常行動中の退場者の残り予定を即時補充敵へ移さない。味方全滅時は残りの優先・通常行動を開始せず敵ターン終了へ進む。
- 味方カード列、味方ターン終了、敵行動列、敵ターン終了は`resolveBattleTurn`が同じ`BattleState`、効果採番、用途別乱数列を順に受け渡す。勝利・敗北は対応するターン終了の最終地点だけで確定し、味方終了時に勝敗確定または次Wave開始となった場合は旧Waveの敵行動を実行しない。
- 戦闘状態は現在の5枚、未配布カード、配布周期、再構築理由を保持し、Wave移行と前衛順変更では同じデッキ状態を引き継ぐ。
- 宝具カードは戦闘個体IDで識別し、戦闘個体の上位宝具定義、宝具Lv、現在有効なカード種別を参照する。選択、チェイン、位置カード値、攻撃入力、条件付きトリガー、ログは同じ有効種別を使い、Hit、N/A、宝具Lv、NPゲージは固有値を維持する。行動不能は共通分類・フラグ、宝具封印は共通効果種別・フラグから判定する。
- `src/effects/classification.ts`の共通行動不能判定を、味方カードと敵行動の両方から使用する。
- `src/effects/traits.ts`は基礎特性と付与中の特性状態を統合した有効特性を返し、対象条件・攻撃威力状態・宝具特殊威力から共用する。付与状態を基礎特性へ書き込まないため、期限切れと解除が自動的に条件判定へ反映される。
- 味方ターン終了コーディネーターと敵ターン終了コーディネーターは、味方退場信号がある場合だけ自動交代後の前衛から次回配布用デッキを再構築する。
- ターン数は開始済みの味方行動フェーズ数とし、次Waveへ進む時も戦闘通算ターンを増やしてWaveターンだけ1へ戻す。
- 同時全滅は味方全滅を先に判定して敗北とし、特殊勝敗条件を進行基盤へ持ち込まない。

## 戦闘ログと乱数監査

- 戦闘ログは完了済み1行動を最小単位とし、Wave番号、戦闘ターン、Waveターン、行動側、行動番号から決定的なIDを作る。
- `BattleState`、関数、`Map`等はログへ保存せず、個体ID・データID・名称と計算・結果のプリミティブだけをJSONへ保存する。
- 味方コマンド開始前のスター配分乱数は行動ログと分けた設定時乱数として記録し、カードごとのクリティカル、効果、ダメージ、スター抽選は所属する行動へ記録する。
- `DeterministicRng`の監査リスナーは乱数列を進めず、整数抽選の範囲・値、確率判定の率・抽選値・成否、内部抽選番号を観測する。0%・100%の確定判定も抽選値なし・消費0回として記録する。
- 1戦闘ターンログは、味方行動列、味方ターン終了、敵行動列、敵ターン終了の順でレコードを保持する。味方終了時に勝敗確定またはWave移行となった場合は、味方行動列と味方ターン終了の2件だけを正常な完了形とする。
- ターン終了レコードは開始・終了状態の要約、終了時発動と子効果、合算HP精算、ブレイク、期限切れ、CT、交代・補充、乱数監査を保持する。終了時チェックポイントは敵行動開始、次の味方入力、Wave移行、戦闘終了を区別する。
- 1戦闘ターンログの外側には親シード、乱数処理バージョン、開始前後の6乱数列位置を保存し、同じ開始状態と操作からログ全体を再現できるようにする。

## 状態・効果基盤

- 戦闘中の各個体は、元データIDとは別の個体IDを持つ。
- 前衛は空き枠を保持し、控えは編成順を保持する。
- 対象解決は`src/effects/targeting.ts`だけで行い、個別データで配列を直接走査しない。
- 状態は`EffectTemplate`から`AppliedEffect`へ変換し、効果個体IDと登録順を採番する。
- 発動候補は、戦闘処理から渡された個体順、優先度、登録順で並べる。
- 発動条件の判定と子効果の付与成功判定は分離する。
- 控え中の個体は、明示的な例外フラグがない限り発動候補に含めず、残りターンも進めない。
- `src/effects/application.ts`は子効果ごとの成功率、耐性、回数制無効を1付与行動単位で解決する。
- `src/effects/modifiers.ts`は共通の成功率・耐性種別と分類限定照合を管理する。
- `src/effects/removal.ts`は解除候補の確定、解除成功率、解除耐性を管理する。
- `src/effects/actions.ts`はHP・NP・状態を変更する宣言的な共通アクションを記述順に実行する。
- `src/effects/declarations.ts`と`src/effects/actionExecution.ts`は`change_np`、`heal_hp`、`reduce_hp`等の固定値・宝具Lv別・OC別宣言を共通の宝具文脈から実行時に解決する。HP減少の`canDefeat`は段階値と独立してデータに必須であり、UIへ値解決を委ねない。
- `src/effects/actions.ts`の複数対象実行は編成順を維持し、HP吸収だけは全対象の減少後に吸収元へ1回回復する。
- `src/effects/maxHp.ts`は基礎最大HPと有効な最大HP変更状態から適用後最大HPを再計算し、付与・解除・期限切れ時の現在HPを調整する。
- `src/effects/hp.ts`は通常HP回復、HP1停止／HP0可能なHP減少、実減少量を使うHP吸収を管理する。
- `src/effects/hp.ts`は同一対象の通常毎ターン回復とスリップダメージを合算し、HP1～最大HPへ1回だけ丸める終了時精算も管理する。
- `src/effects/slipDamage.ts`はやけど・毒・呪いと延焼・蝕毒・呪厄の対応、および発動時の同種倍率照合を管理する。`src/effects/turnEnd.ts`が各スリップ寄与へ発動時倍率を保留し、`src/effects/hp.ts`が種類別基礎量をBigInt整数計算で合計・切捨てする。確定内訳は`src/core/battle/turnLog.ts`へ渡し、データ、保存、UIに同じ計算を重複させない。
- このスリップ倍加経路は統合受入済みであり、発動の前後をまたぐ解除、種類限定耐性との分離、形式4・データ1.38.0の直接復元、固定シードリプレイ、保存済みログだけを表示するUI境界を回帰検査で固定する。
- `src/effects/turnEnd.ts`は味方・敵別の終了時発動、対象解決、共通アクション実行と、双方前衛の明示的な所持者側／相手側期限更新を統合する。
- ターン終了処理は開始時の発動候補と最終登録順を固定し、処理中に追加された状態を次回へ送る。
- 終了時効果の対象指定は状態所持者を基準とし、回復量等の付与者側補正には元の付与者を使用する。
- `turnEndSettlement`が指定された通常毎ターン回復・スリップは対象ごとに保留し、全候補の発動後、状態期限更新前に同時精算する。
- 同時精算指定のない遅延回復やその他の終了時効果は従来どおり発動順で即時実行する。
- `src/effects/defense.ts`は防御状態の優先順、貫通、攻撃／Hit単位の回数消費とダメージ式へ渡す防御値を管理する。攻撃側状態と対象側状態を分けて解決でき、全体攻撃で攻撃側状態を対象ごとに重複消費しない。
- `src/effects/survival.ts`は中間ブレイク、ガッツ、最終死亡、死亡時効果の可否を1か所で確定する。
- `src/effects/instantDeath.ts`は基礎即死率、成功率・耐性・無効を判定してから共通死亡処理を呼ぶ。
- 戦闘個体は`baseMaxHp`と`maxHp`を分けて保持し、一時的な最大HP状態を解除しても基礎値を失わない。
- 戦闘個体は敵・味方とも`deathRatePermille`を持ち、敵データ未設定時は0とする。
- 確率0%以下、100%以上、対象不在では乱数を消費しない。
