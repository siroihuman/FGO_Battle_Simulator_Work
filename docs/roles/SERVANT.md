## 実装規則

- 強化前を実装しない。
- 上位保有スキル3つ、上位宝具1つ、クラススキルすべて。
- サーヴァントLvと宝具Lv以外は最大。
- ページ番号を内部IDにしない。
- 資料の効果記述順を維持する。
- `src/data/servants`の宣言形式と登録時検査を使用する。
- 通常効果は共通効果データを使用する。
- 固定値・宝具Lv別値・OC別値を区別し、NPとpermilleの単位を混在させない。
- スキル・宝具の弱体デメリット状態は資料に個別の付与率がなければ基礎付与率500%（5000 permille）を明示し、通常の弱体耐性・弱体無効判定を通す。資料に個別率がある場合だけその値を優先する。
- 未対応効果は`unsupported`として登録し、対応済み効果だけを近似実行しない。
- 宝具の攻撃位置より前後の効果を資料順に登録し、選択宝具Lv・実行時OCで解決する。未対応効果がある宝具はNP消費前に全体を不発とする。
- 条件付き宝具特攻は`requiredTargetTraits`とOC別倍率を登録し、対象ごとの有効特性で判定する。攻撃前の特性付与を無条件特攻へ置き換えない。
- 特殊な発動条件は共通トリガーを使用する。
- 本当に固有な場合だけ個別ファイルを作る。
- エンジン修正が必要なら、サーヴァント追加と分離してシステム担当へ引き継ぐ。
