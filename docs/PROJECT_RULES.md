# プロジェクト必須規則

仕様書バージョン: 1.0.0

この文書は作業開始時に確認する短縮版です。数値、順序、例外の正確な定義は依頼に関係する [specs/](specs/) を正本として参照します。

## 優先順位

1. 現在のユーザーによる明示指示
2. project-manifest.json とこの文書
3. 詳細仕様
4. 決定記録
5. 実装状況

チャット履歴や記憶だけを根拠に実装しません。

## 戦闘の範囲

- 完全戦闘形式。最終Waveの敵全滅で勝利、味方全滅で敗北、同時全滅は敗北。
- 特殊勝利条件・特殊敗北条件は追加しない。最大3Wave。
- 味方は前衛3騎必須、控え0〜3騎。同一サーヴァントの重複を許可する。
- 敵は全Wave合計1〜99体、同時出現3体または6体、ブレイクは最大10ゲージ。

## 実装の不変条件

- 戦闘は味方行動、味方ターン終了、敵行動、敵ターン終了の順に進め、Wave・勝敗は終了処理の完了後だけ判定する。
- 死亡、交代、敵補充は、原則として1行動の全Hitと効果が終わった安全な境界でだけ処理する。同じ味方戦闘個体の単体通常カードが連続する間だけ、倒した選択対象の退場をその連続区間の終了まで遅らせ、後続通常カードの全Hitを同じ対象へオーバーキルとして処理する。別個体・宝具・全体攻撃への切替では遅らせない。
- 戦闘データIDと戦闘個体IDを分離し、重複編成でもHP、NP、状態、CT、Lv、装備を個別に保持する。
- 同じシード、設定、操作なら、結果と乱数消費順を完全に再現する。
- 戦闘画面のやり直しは、同じシードでは開始時スナップショットと初回手札配布前の全乱数列位置をそのまま使い、違うシードでは同じ開始状態・編成・ロードアウトから新しい具体シードで開始する。どちらも現在の操作履歴・確定ログ・ターンログを引き継がない。
- 中断保存は味方入力待ちまたは終了済みの境界でのみ行い、再開は保存済み状態と全乱数列位置を直接復元する。リプレイ不一致や保存形式不一致を近似して続行しない。
- UI・ログはエンジンの確定結果を使い、戦闘計算や状態遷移を再実行しない。
- UIの状態合算は付与中の同種・同条件の登録値を表示用に正負加算するだけとし、倍率のpermilleは表示時だけ百分率へ変換する。期限・回数・解除・戦闘結果を変更しない。
- 確定結果演出はチェイン、確定HP・味方NP増減、ターン終了、Wave突破を利用者の前後操作で表示する。右上のスキップは既に解決済みの最終BattleSessionを直ちに表示して次の入力またはリザルトへ戻すだけとし、ターンを再実行しない。途中状態を保存・リプレイの正本にせず、攻撃数値は確定行動ログの対象別総ダメージ、各バーは確定前後状態を使い、HP差分からダメージを算出しない。同一個体の連続通常攻撃中は、確定結果ウィンドウ内の敵HP欄へエンジンが返した対象名、最大HP、HP0→0、確定ダメージを表示し続け、その後の確定行動境界で退場を表示する。
- カードのクリティカル表示は保存済みスター配分へQuick始動・Mightyの20%を表示用に合算するだけとし、100%を上限にする。Quick先頭は1枚目選択時点から表示し、解除・先頭変更で戻すが、実判定・乱数・保存済み配分を変更しない。
- 能動カード再配布は味方入力境界・カード3枚提出前だけ使用し、現在前衛の全通常カードから新周期の5枚を配る。宝具カードを混ぜず、`commandStars`／`nextCommandStars`を変更せず、新手札のカード別スター配分をエンジンで確定・保存する。
- カード再配布を含む操作の不正・候補不足・未対応は、状態、CT、履歴、ログ、乱数を変更する前に原子的に拒否する。

## 効果とデータ

- スキル・宝具・礼装の効果説明は、参照Wikiの効果ごとの行分け、順序、接続記号（＋／＆）をそのまま定義へ保存する。複数効果を1行へ要約・統合しない。

- 通常処理は共通効果、限定的例外処理は共通トリガー、固有例外処理だけは対象別モジュールで扱う。
- 有限ターン状態の期限境界は状態データへ明示する。攻撃系強化は所持者側終了、防御系・その他強化は相手側終了、手動状態は自動減算なしとし、終了時トリガーの発動側と期限減算側を混同しない。控え中はどの境界でも進めない。
- ターゲット集中・対粛清防御・無敵・回避・ガッツは同一状態を重複保持しない。すでに有効な状態への再付与は既存状態を更新せず、状態・残りターン・回数・効果採番を変えない付与失敗とする。ただし、弱体ターゲット集中と強化ターゲット集中は別状態として重複し、資料で重複可能と明示した状態だけは`stackable`指定で複数保持する。
- 未対応または不明な効果を近似しない。能動行動は状態・NP・敵チャージ・乱数を変える前に全体を不発とする。
- 魔術礼装・概念礼装の選択は初回カード配布前に1回だけ解決し、概念礼装のATK・HPは戦闘個体別、開始時効果は既存の共通受動効果として適用する。未対応開始時効果は状態・採番・乱数変更前に拒否する。
- `eligibleServantDataIds`を持つ絆礼装は、その厳密なサーヴァント`dataId`へだけ選択・装備できる。同名でもクラス違い・派生霊基は別`dataId`のため対象外とし、UIも候補へ表示しない。
- 絆礼装の「自身がフィールドにいる間」の味方全体効果は、全味方へ解除不能状態として初期化し、発生元と対象の両方が前衛の間だけ登録値を有効にする。交代・自動補充ごとにエンジンが値を更新し、UIは無効値を表示しない。
- 初期概念礼装は最大解放・レアリティ別最大Lv固定とする。各味方戦闘個体0～1枚、未選択可、同一礼装の複数個体装備可とし、所持枚数は管理しない。
- カレイドスコープは装備者の開始NPを100%増加し、黒の聖杯は装備者へ解除不能の宝具威力80%アップと毎ターンHP500減少を付与する。黒の聖杯のHP減少はHP0可能で、HP1停止のスリップ精算へ近似しない。
- 初期敵は`radiant-arm-of-dawn-saber`（黎明の炎腕・剣）1種と、剣基準の極級3 Wave・7個体とする。再利用敵定義と、Wave・戦闘個体ID・Lv・HP・ATK・配置を分離する。
- 初期敵のランダム単体対象と通常攻撃クリティカルは用途別乱数列を使い、敵ターン終了時の通常チャージ増加は生存前衛だけを1増加する。控えとチャージ攻撃未設定敵は進行させない。
- 敵通常攻撃のクリティカル発生率は行動データ基礎値と攻撃者の`critical_chance`状態をpermilleで加算し、0～100%へ制限してエンジンだけが判定する。敵宝具には適用せず、0%・100%は追加の乱数を消費しない。
- やけど・毒・呪いは`slip_damage`の種類として延焼・蝕毒・呪厄だけに対応し、発動時の同種倍率を固定して種類別合計後にpermille倍率を掛け、小数点以下を種類ごとに切り捨てる。対応外スリップとHP0可能なHP減少は倍加しない。
- サーヴァントは強化後の現行データのみ、上位スキル3つ、上位宝具1つ、全クラススキルを資料順に登録する。ページ番号を内部IDにしない。
- 新規サーヴァントの実装では、対象サーヴァント限定の絆礼装を同一PRへ登録する。名称・能力値・効果の資料が不足する場合は補完せず、未確定としてユーザー確認で停止する。
- 再臨段階で名称・スキル・宝具が変わる場合も、共通の再臨段階選択を実装するまではユーザー指定の段階だけを現行定義として登録する。今回は最終再臨を採用し、段階ごとの別サーヴァント定義や個別選択UIを追加しない。
- 編成の公式／オリジナル区分は登録時の明示リストを使い、各区分内をゲーム内通し番号の数値昇順にする。名称やURLから区分を推測せず、タブ閲覧だけで現在選択を解除しない。
- 編成のHPフォウ・ATKフォウは戦闘個体ごとに独立した0～3000の整数、初期値0とする。自由入力は即時にこの範囲へ収め、0／1000／2000／3000の定型ボタンも提供する。選択Lv能力値へフォウ、その後に概念礼装を加算し、UIで最終能力値を再計算しない。
- 登録済みサーヴァントのWiki導線とスキル・宝具説明は定義へ保存した参照URL・登録値だけを使う。保有スキル説明は実装対象のLv10倍率だけを表示し、宝具の宝具Lv別・OC別倍率は維持する。未登録URLや倍率をUIで推測しない。
- 共通のスキル・状態アイコン素材は`public/assets/skill-icons`・`public/assets/status-icons`へ先行登録してよい。ただし、素材が存在することだけを理由に名称から画像を推測せず、各表示対応はユーザー指定または確定仕様で明示する。
- 通常のターゲット集中状態は正式アイコン`Tauntup`を使う。`Enemyfocus`は敵の特殊行動で付与される敵専用状態として予約し、ユーザーの明示指定なしに使用しない。「外道の知識（姉なるもの） EX」は`skill-hp-heal-per-turn`を使う。
- 通常の確率・倍率は整数permilleを使う。資料値が0.1%刻みに収まらない場合は丸めず、該当する共通修正値または基礎率だけを0.01%単位の明示型で追加し、既存の整数permille乱数経路を変更しない。
- スキル・宝具の弱体デメリット状態は資料に個別率がない限り基礎付与率500%を明示登録し、通常の弱体耐性・弱体無効判定を通す。
- 固定値、宝具Lv別、OC別の値を区別する。単体対象は実行時に検査し、特性等で一部の単体効果だけが対象外でも、選択個体へ有効な単体効果が1件以上あればスキル全体を成立させる。対象外の条件付き効果だけを対象なしとして記録する。
- 宣言的HP減少は固定値・宝具Lv別・OC別を共通エンジンで確定し、UIで段階値を再計算しない。HP減少は原則HP0可能とし、味方側スキルが味方側へ与えるHP減少だけはHP1で止める。各データで`canDefeat`を省略せず明示する。
- NP獲得量アップの状態アイコンはカード色限定でも`Npchargeup`を使う。無敵貫通は`Invinciblepierce`、防御無視は`Ignoredefense`を使い、未指定画像を推測しない。
- 〔特性〕特防は特殊耐性へ`requiredAttackerTrait`を明示し、攻撃者の有効特性が一致する攻撃だけに加算する。特防状態のアイコンはユーザー指定の`Defenseup`を使う。
- 「オーバーチャージで追加で強力な攻撃」は主攻撃へ倍率加算せず、同じ宝具行動内の独立した攻撃として主攻撃後に全Hitを実行する。対象が主攻撃でHP0になっても同じ対象を保持し、OC倍率0でもHitを省略しない。
- 攻撃力・カード性能・クリティカル威力等の回数制攻撃強化は1カード／宝具行動につき1回だけ消費する。Hit数・対象数・宝具内追加攻撃数では重複消費せず、クリティカル威力は実際のクリティカル時だけ消費する。
- 防御時クラス相性上書きは通常のクラス相性表を指定値で置き換える。異なる上書き値が同時に有効な場合は未定義として拒否し、加算・乗算で近似しない。
- 敵宝具の宝具LvとOCは戦闘個体・宝具行動ごとの明示値だけを使い、敵Lv、現在／最大チャージ、ターン、Waveから推定しない。段階値を使う行動は開始前に必要文脈と5段階値を一括検査し、欠落・不正・未対応なら固定値へ近似せず、状態・チャージ・効果採番・乱数変更前に全体を不発とする。
- 味方・敵のターン終了トリガーによるスター獲得は、どちらもプレイヤーの次回味方コマンド用へだけ資料順に加算し、各加算時点で99個を上限とする。現在使用分への指定、控え中の発動、終了処理やUIでの再計算を許さない。

## 検査と更新

- 変更範囲の回帰テストを追加し、npm test、npm run typecheck、npm run build を実行する。
- コア規則・データ形式を変えた場合は project-manifest.json、挙動を変えた場合は該当仕様書、進捗を変えた場合は IMPLEMENTATION_STATUS.md と START_HERE.md を同じPRで更新する。
- 新しい方針は DECISION_LOG.md に短く記録し、詳細な理由や完了履歴は [archive/](archive/) へ保存する。
