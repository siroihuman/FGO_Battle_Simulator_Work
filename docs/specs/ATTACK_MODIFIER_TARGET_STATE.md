# 攻撃補正の対象状態条件仕様

仕様書バージョン: 1.0.0

## 目的

攻撃元へ付与されている通常の攻撃補正について、攻撃対象が特定の防御状態を所持している時だけ値を有効にする共通条件を定義します。サーヴァント名や概念礼装名による分岐は作りません。

最初の対応対象は、No.059「那須与一」の強化後宝具と絆礼装に共通する「回避または無敵状態の敵」に対する威力補正です。

## 宣言条件

- 攻撃元の`AppliedEffect.flags.requiredTargetEvadeOrInvincibility`が`true`の時だけ、この条件を使用する。
- 条件対象は現在の攻撃対象1体とする。
- 対象の付与中状態に`effectType = evade`または`effectType = invincibility`が1件以上存在すれば成立する。
- `evade`と`invincibility`の両方が存在しても、1個の攻撃元効果は1回だけ加算する。
- `solemn_defense`だけを持つ対象では成立しない。
- 条件を付けていない既存攻撃補正の挙動は変更しない。

## 判定タイミング

- `before_attack`と宝具攻撃前宣言効果が完了し、対象ごとの攻撃入力を構築する時点の状態を読む。
- 防御解決による回避・無敵の回数消費より前に条件を確定する。
- 攻撃元が必中または無敵貫通を持っていても、対象の回避・無敵状態そのものが存在する限り条件は成立する。貫通は防御を無効化する処理であり、この対象状態条件を消去しない。
- 条件照合そのものは状態を付与・解除・消費せず、乱数も消費しない。

## 攻撃補正への接続

既存の`resolveAttackModifierTotals`と同じ攻撃元補正の照合処理を使用します。したがって、以下を含む既存の攻撃元補正と組み合わせられます。

- `noble_phantasm_damage`
- `critical_damage`
- `power`
- `attack`
- `card_performance`
- `fixed_damage`
- `np_gain`
- `star_generation`

個別データ側は必要な効果種別、値、既存の`attackKind`・`criticalOnly`等と、この対象状態条件を組み合わせます。

## No.059「那須与一」への予定接続

- 強化後宝具の「回避または無敵状態の敵に対する宝具威力50%アップ」は、`noble_phantasm_damage = 500`、`attackKind = noble_phantasm`、`requiredTargetEvadeOrInvincibility = true`として表現する。
- 絆礼装の「回避または無敵状態の敵に対するクリティカル威力30%アップ」は、`critical_damage = 300`、`criticalOnly = true`、`requiredTargetEvadeOrInvincibility = true`として表現する。
- 絆礼装の名称が参照資料で未確定のため、この共通機能PRには那須与一本体・絆礼装データを含めない。名称を推測して登録しない。

## 互換性

- `EffectFlagValue`の型は変更しない。既存のbooleanフラグを追加するだけとする。
- BattleSession、中断保存形式4、データ形式1.38.0、行動ログ形式5、ターンログ形式2を変更しない。
- 6本の用途別乱数列を追加・削除・並べ替えしない。
- UIへ条件判定を複製せず、確定したエンジン結果だけを表示する。

## 回帰検査

最低限、同一の条件付き攻撃元効果について次を検査します。

1. 対象に回避も無敵もない場合は0。
2. 回避だけなら有効。
3. 無敵だけなら有効。
4. 回避と無敵の両方でも1回分だけ有効。
5. 対粛正防御だけなら0。
6. 通常クリティカルの条件付きクリティカル威力と、宝具の条件付き宝具威力の双方で同じ対象状態条件を使用できる。
