# 新しいChatGPTチャットの開始方法

仕様書バージョン: 1.0.0

過去チャットの長い要約は使わず、リポジトリの短い入口文書から再開します。

## 基本手順

1. 新しいチャットを開く。
2. 下記の開始文へ担当役割と依頼を追記する。
3. 作業者が `AGENTS.md`、`docs/START_HERE.md`、`docs/PROJECT_RULES.md`、`docs/IMPLEMENTATION_STATUS.md`、担当役割の文書、関係する仕様・テンプレート・実装・テストを読んだことを確認する。
4. コア規則・データ形式・システムを変える場合は、追加で `project-manifest.json` と必要な詳細文書を読む。
5. 専用ブランチとPRで作業する。

## 共通開始文

```text
FGOバトルシミュレーターの作業をお願いします。

リポジトリ:
https://github.com/siroihuman/FGO_Battle_Simulator_Work

基準ブランチ:
main

チャットの記憶ではなく、リポジトリを唯一の正本として扱ってください。
変更前に AGENTS.md、docs/START_HERE.md、docs/PROJECT_RULES.md、
docs/IMPLEMENTATION_STATUS.md、担当役割の文書、
関係する仕様書・テンプレート、実装ファイル、テストを読んでください。
コア規則・データ形式・システムを変える場合は project-manifest.json、
docs/ARCHITECTURE.md、必要な詳細仕様書も読んでください。

現在のユーザー指示と文書が衝突する場合は、ユーザー指示を優先し、
同じ変更で仕様書・決定記録・テストも更新してください。

読み取った仕様書バージョン、現在の実装段階、今回編集する範囲を
作業開始前に短く報告してください。

今回の担当:
（システム／サーヴァント／概念礼装／魔術礼装／敵）

今回の依頼:
（ここへ記入）
```

## 役割ごとに分ける

複数種類のデータ追加を同じチャットへ混在させず、次の単位でチャットを分けます。

- システム実装
- サーヴァント実装
- 概念礼装実装
- 魔術礼装実装
- 敵実装
- 不具合修正

詳細な完了履歴や過去の決定理由が必要なときだけ `docs/archive/` を開きます。

## 作業終了時

```text
作業終了前に、テストを実行し、現在地点・次の作業・該当する仕様書を更新してください。
PR本文には参照資料、処理分類、確認結果、未確認事項を記載してください。
次のチャットが必要な場合は docs/HANDOFF_TEMPLATE.md の形式で引継ぎを残してください。
```

## 認識差を見つけた場合

- チャットだけで修正せず、正しい内容を仕様書へ反映する。
- 新しい判断は `docs/DECISION_LOG.md` へ短く記録し、詳細な理由はアーカイブへ残す。
- 関係する自動テストを追加する。
- 古い説明が残っていないか検索する。
