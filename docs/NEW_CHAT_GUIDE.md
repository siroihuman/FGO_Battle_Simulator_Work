# 新しいChatGPTチャットの開始方法

仕様書バージョン: 1.0.0

チャットが重くなった場合、過去チャットの長い要約を作り直す必要はありません。最新の仕様と進捗はリポジトリに保存します。

## 基本手順

1. 新しいチャットを開く。
2. 下記の開始文を貼る。
3. 今回の担当役割と具体的な依頼を追記する。
4. ChatGPTが必須文書と実際のファイルを読んだことを確認する。
5. 作業は専用ブランチとPRで行う。

## 共通開始文

```text
FGOバトルシミュレーターの作業をお願いします。

リポジトリ:
https://github.com/siroihuman/FGO_Battle_Simulator_Work

基準ブランチ:
main

チャットの記憶ではなく、リポジトリを唯一の正本として扱ってください。
変更前に AGENTS.md、project-manifest.json、docs/INDEX.md、
docs/PROJECT_RULES.md、docs/IMPLEMENTATION_STATUS.md、
担当役割の文書、関係する仕様書・テンプレート、実装ファイル、テストを読んでください。

現在のユーザー指示と文書が衝突する場合は、ユーザー指示を優先し、
同じ変更で仕様書・決定記録・テストも更新してください。

読み取った仕様書バージョン、現在の実装段階、今回編集する範囲を
作業開始前に短く報告してください。

今回の担当:
（システム／サーヴァント／概念礼装／魔術礼装／敵）

今回の依頼:
（ここへ記入）
```

## 役割ごとに分ける

複数種類のデータ追加を同じチャットへ混在させず、次の単位でチャットを分けることを推奨します。

- システム実装
- サーヴァント実装
- 概念礼装実装
- 魔術礼装実装
- 敵実装
- 不具合修正

役割ごとの変更範囲は `docs/roles/` に保存しているため、チャットを変えても同じ規則を使用できます。

## 作業終了時

ChatGPTへ次を依頼します。

```text
作業終了前に、テストを実行し、該当する仕様書と
docs/IMPLEMENTATION_STATUS.mdを更新してください。
PR本文には参照資料、処理分類、確認結果、未確認事項を記載してください。
次のチャットが必要な場合はdocs/HANDOFF_TEMPLATE.mdの形式で引継ぎを残してください。
```

## 認識差を見つけた場合

- チャットだけで修正せず、正しい内容を仕様書へ反映する。
- なぜ変更したかを `docs/DECISION_LOG.md` へ記録する。
- 関係する自動テストを追加する。
- 古い説明が残っていないか検索する。

この手順により、毎回長い会話を読み込ませるのではなく、必要な役割文書と仕様だけを読ませられます。
