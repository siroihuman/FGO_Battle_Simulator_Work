# 決定記録

仕様書バージョン: 1.0.0

この文書は決定理由を失わないための追記式記録です。過去の決定を削除せず、変更時は新しい項目を追加します。

## D-001 リポジトリを唯一の正本とする

- 日付: 2026-07-30
- 状態: 採用
- 決定: チャット履歴より、リポジトリ内の仕様書、決定記録、現在状況、テストを優先する。
- 理由: 長いチャットを変更した際の記述ブレと認識差を防ぐため。

## D-002 効果を3分類する

- 日付: 2026-07-30
- 状態: 採用
- 決定: 通常処理、限定的例外処理、固有例外処理へ分ける。
- 理由: 戦闘エンジンの肥大化と重複処理を防ぐため。

## D-003 計算とUIを分離する

- 日付: 2026-07-30
- 状態: 採用
- 決定: UIは戦闘エンジンの結果だけを表示し、独自計算を持たない。
- 理由: パソコン版とスマートフォン版で結果が変わることを防ぐため。

## D-004 固定シードを再現保証に使用する

- 日付: 2026-07-30
- 状態: 採用
- 決定: シード、設定、操作が同じなら結果を完全一致させる。
- 理由: 不具合再現と計算検証を容易にするため。

## D-005 全滅戦だけを実装する

- 日付: 2026-07-30
- 状態: 採用
- 決定: 特殊勝利条件・特殊敗北条件を除外する。
- 理由: ユーザーの明示指定と、初期基盤の範囲明確化のため。

## D-006 計算・戦闘基盤を追加データより優先する

- 日付: 2026-07-30
- 状態: 採用
- 決定: サーヴァント、礼装、敵の大量追加より先に共通基盤とテストを完成させる。
- 理由: 後からデータを増やしても同じ規則で動かせるようにするため。

## D-007 乱数を用途別の独立列へ固定する

- 日付: 2026-07-30
- 状態: 採用
- 決定: SplitMix64を乱数処理バージョン1とし、単一シードからカード、AI、効果、クリティカル、ダメージ、スターの6列を生成する。
- 理由: 効果追加等で無関係な計算結果がずれることを防ぎ、保存状態から完全に再開するため。

## D-008 計算途中は安全な整数とBigIntを使用する

- 日付: 2026-07-30
- 状態: 採用
- 決定: 公開APIは安全な整数を受け取り、乗算途中はBigIntで保持し、仕様上の地点だけで切り捨てる。
- 理由: 浮動小数点誤差と、乗算途中の安全整数範囲超過を防ぐため。
